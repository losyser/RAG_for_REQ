# 需求映射独立专家审核（本机中文版）

双击桌面“需求映射专家审核”，或运行本目录 launch.ps1。只访问 http://127.0.0.1:8769 。后台是 Python 标准库服务，无网络依赖、无模型调用。启动使用 `-I` 隔离模式，避免旧 Tribon 的环境变量污染。

## 专家操作

1. **新建审查**：填写自己的代号。当前先使用“隔离练习”；正式审查须导入协调者提供的已确认任务包。
2. 先阅读原始需求，在完整分类目录中添加独立首判配对。确认后首判锁定，再显示候选。
3. 每个候选选择“相关 / 不相关 / 不确定”。“未答”不是“不相关”。
4. 查看完整 taxonomy，补充候选池以外的相关或不确定配对，并确认本条源需求已经完成查漏。
5. 中文备注自动保存；“保存”立即写入本机。**导出备份**下载 JSON，可用“打开旧审查”恢复。CSV 包含候选、首判、补漏和中文备注，不能作为恢复文件。
6. 同一电脑交给下一位专家前，先导出备份，再点“离开审查”；下一位新建任务。网页不提供全部任务列表。

每个任务独立保存到 `local_records/<任务ID>.json`，上一版保存在同目录 `.previous.json`。自动保存约在最后输入后 0.7 秒开始；浏览器同时保留当前任务的恢复副本。正常关闭后重开入口会恢复；浏览器清理缓存后用 JSON 备份打开。未保存时关闭页面会提示；保存失败时用“导出待保存副本”。不要依赖浏览器缓存作为唯一备份。

## 版本冲突与损坏保护

不要在两个窗口同时编辑同一任务。服务按修订号拒绝过期覆盖；遇到冲突，先导出待保存副本，再重新打开最新备份。本地文件损坏时禁止覆盖，可从有效 JSON 备份恢复为**新任务副本**，保留原损坏文件和来源任务 ID。导入文件须通过结构与 SHA256 校验；校验用于发现意外损坏，不是评审身份数字签名。

任务 JSON 备份含该任务的访问凭据和专家答案，请按原始研究记录保管。隔离保护是应用内的任务级访问控制，不防止拥有本机文件权限的人员查看磁盘或浏览器数据。服务不会读取或发送项目 PRIVATE 文件、expert_key.json、.env 或任何模型 API 密钥。

## 正式样本确认后（仅协调者）

本轮没有生成正式任务包。确认抽样方案后，显式列出完整源需求 ID 与协议编号；不得按模型得分挑选。例子仅说明命令格式，不代表选定样本：

```powershell
python -I server.py --prepare-assignment "已确认任务包.assignment.json" --source-ids "经批准的ID1,经批准的ID2" --protocol "已确认协议编号"
```

输出必须是新文件；同一包交给每位评审，各自新建。源需求原文、完整 taxonomy、候选池与来源 SHA256 嵌入包和后续原记录。源 ID 列表必须由确认后的抽样方案提供，工具不自动抽样。首判先隐藏候选，后续候选来自合并池，仅显示配对，不显示方法或预测标签。候选在任务包中并非加密，评审应遵守先独立首判的流程。

原始中文 JSON 是保留记录；任何英文论文材料应另建文件并引用任务 ID、数据版本及修订号。不把练习、AI 辅助参考集或旧版预测性能冒充独立正式 gold 或 v4 主实验性能。不确定需保留，工具不自动裁决或输出论文分数。

## 测试

`python -I test_review.py` 运行工具的本地无模型测试。浏览器验收使用独立 `--data-dir` 与测试端口，不写正式记录。验证报告及截图见交付目录。

## 停止与回溯

关闭浏览器不停止后台，重新启动入口会复用健康的本机服务。若需停止，只停止命令行为本目录 server.py 的 Python 进程；不要批量停止其他 Python。项目独立 Git 快照记录基线与本次工具版本，原项目 Git 索引保持不变；恢复应导出到新目录，避免 reset/clean 原项目。
