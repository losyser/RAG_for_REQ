# RAG 可信度证明：项目重规划设计

**日期**: 2026-05-30
**状态**: 已通过 brainstorming，待用户复核
**取代**: 原「多粒度优越性」叙事（已被 grounding 动作 A 证伪，见 `project_grounding_result`）

---

## 0. 背景与重定向

原项目把「多粒度检索提供更好证据」当成头条命题，已被 grounding score（动作 A）证伪：扁平检索的逐条证据契合度 ≥ 多粒度，2/3 测法显著。更根本的问题是 M1（无证据率）作为跨组可信度度量是**循环的**——G1 不检索，天生无证据，拿这个比毫无意义。

本设计把项目重新锚定到**真正的核心命题**，并把多粒度/ranker/profile 降格为辅助消融。

---

## 1. 核心命题与可证伪判据

**核心命题**：在同一把 KB 真值尺子下，「据检索证据生成的工程需求」比「无检索、据子需求直接生成」具有**更低的幻觉率、更低的过推断率**，以及更高的可溯源可信度。

**可证伪**：若 RAG 组在配对子集上幻觉率/过推断率不显著低于 no-RAG 组，则命题伪（或度量错）。按学术诚信如实报告，不调参凑数。

**定位**：多粒度、ranker、profile 等**全部是辅助手段**，只用于消融说明「如何把 RAG 系统做得更好」，不是头条。不本末倒置。

---

## 2. 实验组设计（主对比 + 消融）

| 组 | 拆分 | 检索 | 生成依据 | 作用 |
|---|---|---|---|---|
| **B0** no-RAG | 共享拆分 | 无 | 据子需求生成 | **头条基线** |
| **R** RAG-full | 共享拆分 | 多粒度+ranker+profile | 据证据生成；无证据不产出 | **头条系统** |
| A1 | 共享拆分 | 仅扁平单粒度 | 据证据 | 消融：多粒度贡献 |
| A2 | 共享拆分 | 多粒度，关 ranker | 据证据 | 消融：ranker 贡献 |
| A3 | 共享拆分 | 多粒度，关 profile | 据证据 | 消融：profile 贡献 |

**头条只有 B0 vs R。** 两组**共享 DeepSeek 的同一份子需求拆分**，唯一差别 = 「上下文中是否注入检索证据 + 据证据约束生成」。这是干净的单变量实验。

A1/A2/A3 进消融与讨论。已知 grounding 结论（扁平 ≥ 多粒度的逐条契合度）如实进消融，不藏。

## 3. 指标体系（破循环，两组同判）

### 主指标
- **H 幻觉率 ↓**：裁判抽取每条 shall 的事实 claim（数字/阈值/标准/设计规则）→ 拿 KB 回溯 → 判「支持/矛盾/找不到」。
  - **硬幻觉 H_hard**：claim 被 KB **明确矛盾**（断言的数字/阈值与 KB 冲突）。与措辞无关、不受检索偏置影响，**以此为主**。
  - **软幻觉 H_soft**：claim 在 KB 中**查无**。用强语义检索 + 大 top-k 兜底，标注其对检索敏感。
- **OI 过推断率 ↓**：claim 中超出「原始需求 + KB 授权范围」、凭空添加的义务/约束（范围蔓延），即便不是硬事实错。

### 辅助指标
- **G 可溯源契合度 ↑**：复用现有 grounding 工具（reranker + 跨厂商 LLM 蕴含）。no-RAG 也做**事后**检索回溯打分，保证公平。
- **Rel 相关性 ↑**：shall 是否真正回应原始需求（防止 R 靠「少答」降幻觉）。
- **Cov 覆盖率**：每组实际产出需求数 / 子需求数。**显式报告 R 的弃权**，诚实呈现精度-覆盖权衡。
- **次要**：可验证性、MBSE 完整性（沿用旧 M4/M5）。

### 明确弃用
- **M1 无证据率**不再作为跨组可信度度量（循环）。可保留为系统描述性统计，但不参与 B0 vs R 的可信度结论。

### H/OI 的精确区分
- **H**：断言的**具体事实**（数字/阈值/标准）被 KB 矛盾或查无。关乎事实正确性。
- **OI**：超出原始需求 + KB 授权范围、凭空加的**义务/约束**（范围蔓延）。即便每个事实都对，也可能 OI。

## 4. 干净性保障（逐条堵住偏置/循环）

这是本设计的核心。每一条都是为了「思路干净正确」。

### 隐患 1：H 度量偏袒 RAG（最隐蔽的循环）
R 据 KB 生成，文字与 KB 措辞接近，检索回溯易命中；B0 即便事实正确、措辞不同，检索可能找不到→误判幻觉。
- **补法**：硬幻觉/软幻觉分开报，**以硬幻觉为主**（硬幻觉 = 被 KB 明确矛盾，与措辞无关）。软幻觉用强语义检索 + 大 top-k，并标注其检索敏感性。

### 隐患 2：R 弃权导致不公平
R 只在有证据处生成、少答难题，自然幻觉低，会被质疑「挑软柿子」。
- **补法**：**头条 = 配对子集比较**。只在「R 确实产出 shall」的子需求上，拿 R 的 shall 对 B0 同一子需求的 shall 比 H/OI。同一子需求、同一 KB 尺子，唯一差别 = 上下文有无检索证据。这是最干净的单变量因果。
- 同时**显式报告 Cov**，并给端到端率（R 弃权计入）作为「实际工程可信度」补充。两个都给，不藏弃权。

### 隐患 3：B0 不能是稻草人
- **补法**：B0 与 R **共用同一套基础 prompt**（同模型 Qwen、同温度、同输出格式、同「无依据不得编造数字」安全条款）。**唯一差别** = R 上下文多了检索证据块 + 「以证据为唯一事实源」指令。treatment 严格是「上下文有无检索证据」这一个变量，其余全 held。

### 隐患 4：裁判独立性
生成用 Qwen，裁判不能是 Qwen。reranker 只给相关度、判不了「矛盾」，故「支持/矛盾/找不到」需要 NLI 式 LLM。
- **补法**：跨厂商**双 LLM 裁判**——文心 ERNIE + DeepSeek（DeepSeek 只做过拆分、没生成被判的 shall，独立于生成）。reranker 给客观契合度。三者交叉、报一致性（如 Cohen's κ / 多数投票）。
- **加人工校准**：抽 ~50 条 claim 人工裁定，与自动裁判比对，确认裁判没系统性冤枉 B0。人工裁定为最终背书。

### 隐患 5：ERNIE 原始需求污染
- **补法**：原始需求是高层运行需要，**不得照抄 KB 证据原文**；生成后做质量核查（措辞独立性、真实性、难度分布），冻结版本化。

## 5. 数据构造（多智能体跨厂商分工）

生成者 ≠ 裁判者 ≠ 出题者，三方异厂，系统性规避自评偏袒。

| 角色 | 模型 | 职责 |
|---|---|---|
| 出题 | **文心 ERNIE** | 生成 N 条逼真的船舶冷却水**原始需求**，冻结版本化 |
| 拆分 | **DeepSeek** | 把每条原始需求**拆分**成子需求（两组共用） |
| 生成 | **Qwen** | 据检索证据**生成工程需求** |
| 裁判 | **ERNIE + DeepSeek + reranker** | 幻觉/蕴含判定（跨生成者），+ 人工校准 |

注意：ERNIE 既出题又当裁判——但裁判判的是 shall-vs-KB，不是 shall-vs-原始需求，故出题角色不直接污染 KB 接地的 H 判定。仍以 reranker（客观）+ 双 LLM + 人工校准多重背书。

约束（沿用安全规约）：
- 所有 API key 仅存 `.env`，永不硬编码、永不进 git。
- 仅 DeepSeek、Qwen、文心可用 API；ChatGPT/Codex 只能人工。

---

## 6. 生成环节改造（证据优先）

现有「据子需求生成」→ 改为：
1. 子需求仅用于**驱动检索**。
2. 命中证据的子需求才进入生成；prompt 把**检索到的证据**作为唯一事实来源，显式要求「证据未覆盖的参数不得编造」。
3. 无证据的子需求**直接弃权**（记入 Cov），不产出 shall。

B0 走同一拆分，但跳过检索，prompt 不含证据块（其余 held）。

## 7. 统计方案

- **配对单位**：头条用**子需求级**（R 产出的子需求子集），B0 同子需求配对；稳健性旁证用唯一 `source_requirement_id` 级。
- **去重**：沿用已修复的伪重复处理——T>0 下多轮重跑同一项按均值聚合，避免 n 夸大、p 失真（见 `grounding.py` / commit 30d5c7f）。
- **检验**：配对 Wilcoxon + bootstrap 95% CI（复用 `grounding.paired_compare`）。主对比在 H_hard / H_soft / OI / G / Rel 各一检验；消融同法。
- **样本量**：原始需求池 ≥ 60 条，去重后保证检验功效。
- **裁判一致性**：报双 LLM + reranker 的一致性，及人工校准子集的吻合度。

## 8. 复用现有资产

- **保留**：三粒度索引、检索 pipeline、`grounding.py`（RerankerScorer / LLMEntailmentScorer / paired_compare / 去重聚合）、config 的 Qwen/ERNIE 客户端。
- **新增**：claim 抽取模块、KB 回溯判定（H_hard/H_soft/OI）评估层、证据优先生成的 prompt 改造、ERNIE 原始需求生成器。
- **改造**：生成环节从「据子需求」改「据证据」。

## 9. 里程碑（0 → 发表）

（用「阶段」前缀，避免与 §3 指标的 M1/M4/M5 命名冲突）

1. **阶段 1 数据集**：ERNIE 生成 + 冻结原始需求池（含质量核查）；DeepSeek 拆分。
2. **阶段 2 评估层**（TDD）：claim 抽取 + KB 回溯判定（H_hard/H_soft/OI），跨厂商双裁判 + reranker；先在小样本验证判定一致性 + 人工校准。
3. **阶段 3 生成改造**：证据优先生成，B0 / R 两条产线跑通（共用基础 prompt，仅证据块差异）。
4. **阶段 4 主实验**：B0 vs R 全量，出 H_hard/H_soft/OI/G/Rel/Cov；头条配对子集 + 端到端率。
5. **阶段 5 消融**：A1/A2/A3。
6. **阶段 6 论文**：重写叙事——头条「RAG 证据约束降幻觉、提可信度」，多粒度等进消融与讨论。

## 10. 验证威胁与缓解（汇总）

| 威胁 | 缓解 |
|---|---|
| H 度量措辞偏置 | 硬幻觉为主（与措辞无关）；软幻觉强检索 + 标注敏感性 |
| R 弃权挑软柿子 | 配对子集为头条 + 显式报 Cov + 端到端率 |
| B0 稻草人 | 同模型/温度/格式/安全条款，唯一差别为证据块 |
| 裁判自评偏袒 | 生成≠裁判跨厂商；双 LLM + reranker + 人工校准 |
| 原始需求污染 | 不抄 KB；质量核查 + 冻结 |
| 伪重复 / T>0 | 按唯一项聚合取均值 |
