# RAG vs no-RAG 工程需求质量与可靠性对比 — 设计

**日期**：2026-05-30
**状态**：已通过 brainstorming，待用户复核

## 1. 命题与可证伪

**核心命题**：经 RAG（检索增强）转化得到的工程需求，比无 RAG 直接由 LLM 转化的，**质量更高、更可靠、更能支撑工程**。

证的是"RAG 这条转化路径更优"，**不是**"LLM 不能转化需求"。no-RAG 必须是**强基线**（充分发挥 LLM 能力），不能是被阉割的语言润色机。

**可证伪**：若在公平、非循环度量下，RAG 组的质量胜率不显著高于 no-RAG、且矛盾率不显著更低，则命题不成立。守学术诚信，不调参凑结果。

## 2. 两条产线（系统级对比，非单变量）

诚实声明：这是**整条路径的系统级对比**，两组在多处不同（检索内容生成、检索、证据接地），头条claim是"RAG 路径更好"，组件级贡献由消融说明。

**no-RAG**：
```
原始需求 → DeepSeek（强基线 prompt）→ 工程需求
```
强基线 prompt：要求充分运用领域知识，产出完整、具体、可指导施工的专业工程需求（含必要参数/阈值），明确**不准只做语言润色**，模拟"工程师直接用 LLM 把原始需求转成工程需求"的真实场景。

**RAG**：
```
原始需求 → Kimi 生成检索内容（组成对象等关键词 + 适检中/英文句子）
        → 覆盖率优先检索（多查询并集、大 top_k、放宽过滤）
        → DeepSeek 据检索证据生成工程需求（生成时先判证据相关性再用）
```

**两组终端生成都用 DeepSeek**（模型一致，差别落在"有无 RAG 增强"），排除模型能力混淆。

## 3. 多智能体分工（四模型跨厂商）

| 角色 | 模型 | 职责 |
|---|---|---|
| 出题 | ERNIE | 原始需求（复用冻结 `original_requirements_v1.jsonl` 60 条） |
| 检索内容生成 | **Kimi (Moonshot)** | 由原始需求生成关键词 + 中/英检索句（仅 RAG） |
| 工程需求生成 | DeepSeek | 两组的工程需求生成 |
| 裁判 | Qwen | 可靠性 KB 回溯判定 + 盲评质量对比 |
| 客观契合度(辅) | BGE-reranker-v2-m3 | 描述性，不作头条 |

生成(DeepSeek) ≠ 裁判(Qwen) ≠ 检索内容生成(Kimi) ≠ 出题(ERNIE)，互不背书。
Kimi：`KIMI_API_KEY`/`KIMI_BASE_URL`(=https://api.moonshot.cn/v1)/`KIMI_MODEL`，仅 `.env`，已验证连通。

## 4. 检索改造（覆盖率优先，精准其次）

- Kimi 输出多条检索内容（关键词 + 中/英句），各自检索后**取并集**提升召回覆盖。
- 放大 top_k、放宽 applicability 过滤，覆盖优先。
- **精准交给生成端**：DeepSeek 生成时对每条检索证据先判相关/可用再据以生成，降低"覆盖换噪声"导致的证据误读（针对上一版发现的 R 误读证据问题，如错误生成"不应使用铜镍合金"）。

## 5. 评估体系（多维，不单凭一指标）

### A. 可靠性（KB 锚点，Qwen 两组同判）
- 每条工程需求抽事实主张（参数/阈值/规则）→ 对 KB 权威语料 + 领域常识判 **支持 / 被矛盾 / 查无**。
- **主指标：矛盾率（硬幻觉）↓**（被 KB 明确矛盾，与措辞无关，公平）。
- 过推断率 ↓。
- 查无率单列（对 KB 覆盖敏感，**只描述、不作可靠性结论**——吸取上一版 H_soft 教训）。
- no-RAG 也做 KB 事后回溯，**不因"没引用"受罚**（破 M1 循环）。

### B. 质量（盲评两两对比，Qwen + 人工抽检）
- 同一原始需求下，B0/R 两份需求**匿名、随机打乱左右**交 Qwen，逐维判 胜/平/负：
  - 完整性、具体可操作性、内部一致性、可验证性。
- **主指标：质量胜率**（R 胜 / 平 / 负 的占比）。
- 为防位置偏置：每对**正反各评一次**（交换左右），取一致结果。

### C. 描述性（只报，不作质量裁定，避免循环）
- 可溯源率、覆盖率、具体参数占比、篇幅长度。

### D. 人工验证
- 抽样核对 Qwen 的可靠性判定与盲评结论是否可信（一致率 + 关键分歧复核）。

---

## 6. 防循环 / 防偏置（吸取前几轮教训）

| 隐患 | 对策 |
|---|---|
| no-RAG 被阉割成润色机 | 强基线 prompt，允许/要求具体参数，暴露真实幻觉 |
| "没引用"被当不可靠 | 可靠性走 KB 事后回溯；质量鱼骨不含引用/可溯源 |
| 措辞偏置（查无≠幻觉） | 矛盾率为主；查无率只描述 |
| 裁判主观/位置偏置 | 盲评匿名 + 左右交换双评 + 跨厂商(Qwen) + 人工抽检 |
| 覆盖换噪声致误读 | 生成端先判证据相关性再用 |
| 同源相似 | 取消共享拆分，两组各走各的路径 |

- **头条**：整条 RAG 产线 vs 整条 no-RAG 产线 —— **质量胜率** + **矛盾率**（+ 过推断、人工验证）。

## 9. 里程碑（路线图，细节随上游产物再定）

1. Kimi 配置 + 检索内容生成（TDD）。
2. no-RAG 强基线生成器 + RAG 产线（Kimi→覆盖检索→DeepSeek 据证据生成）。
3. 跑两条产线（复用 60 原始需求），产出两组工程需求。
4. 可靠性评估（矛盾率/过推断，Qwen KB 同判）+ 盲评质量裁判（左右交换）。
5. 人工抽检校准。
6. 消融 + 论文叙事。

## 10. 验证威胁与缓解（汇总）

| 威胁 | 缓解 |
|---|---|
| 系统级对比多处不同，难归因 | 诚实声明为路径对比 + 消融拆 Kimi/检索策略 |
| 覆盖优先引入噪声伤 R 可靠性 | 生成端证据相关性过滤 |
| 裁判（Qwen）不可靠 | 人工抽检 + 左右交换 + 跨厂商 |
| no-RAG 强基线 prompt 调成稻草人或过强 | prompt 中立专业，模拟真实用户用法，人工审 prompt |
| KB 覆盖限制可靠性可比性 | 矛盾率为主（不受覆盖影响），查无率只描述 |
